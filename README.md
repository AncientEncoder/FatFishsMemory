# FatFishsMemory

> 给 DeepSeek Harness 的**类人记忆**插件：上下文满了不丢事，而是像人一样分层记住。

DSH 的窗口是 1,048,576 tokens。装满了，最早的对话会被挤掉——表现就是「它忘了我」。
框架本来就会压缩（`compaction/start|prune|summary|end`），**但它压完就丢了**。

这个插件不重新发明压缩，只做三件事：

1. **把压掉的东西留下来** —— 每轮原文归档，可按线索检索
2. **把该记住的提炼出来** —— 记忆卡、用户画像、任务边界
3. **在该想起来的时候提醒一句** —— 会话开始时给目录，问旧事时先查表

零依赖、零网络调用、纯本地。

## 快速开始

```bash
# 从源码装
dsh plugin --profile desktop add file:D:\Work\Code\FatFishsMemory

# 或者从 release 包装
dsh plugin --profile desktop add file:<解压目录>
```

装完**重启 DSH**。之后什么都不用做——它自己开始记。

## 三层记忆

| 层 | 存什么 | 代价 | 谁管 |
|---|---|---|---|
| 热 | 当前上下文窗口 | 最贵，满了被挤掉 | 运行时 |
| 温 | 记忆卡、画像、目录 | 极便宜，常驻 | 本插件 |
| 冷 | `turns.jsonl` 原文、增量块 | 磁盘，按线索召回 | 本插件 |

**热层我们不管**——它由运行时控制（何时压缩、压多少）。伸手进去改会被反噬（见「设计决策」）。

我们的价值全在温层和冷层，外加一句「**该查就查**」。

### 最初的构想

这个项目的起点是一张手画的草图（项目发起人提出的）：

```
        ┌───────────────────────────────┐
  热    │ 当前推理的 KV / 上下文窗口      │  最贵，满了就被挤掉
        └───────────────┬───────────────┘
                        │ 满了就压
        ┌───────────────▼───────────────┐
  温    │ 摘要索引：一条记忆 = 一行       │  便宜、常驻、可检索
        │ （时间 / 目标 / 结果 / 关键词）  │
        └───────────────┬───────────────┘
                        │ 要细节时回溯
        ┌───────────────▼───────────────┐
  冷    │ diff 归档：原文按块存           │  磁盘，不占上下文
        └───────────────────────────────┘
```

实现时变了三处，如实记下来：

| 构想 | 实际 | 原因 |
|---|---|---|
| 热 = KV cache | ❌ 上下文窗口 | 插件碰不到推理层 |
| 温 = 摘要索引 | ✅ 记忆卡 + 画像 | 照做 |
| 冷 = diff 归档 | ✅ 前缀/后缀 delta | 见下 |

### 为什么敢有损

出发点不是"存得多"，是**"重塑得要像"**。人的记忆也是这么工作的：
你不会记得上周二每句话，但记得"那天在修服务器，最后是网线的问题"。

三条原则：

1. **热层不省，省在别处** —— 上下文只放"此刻要用的"
2. **有损压缩的前提是原文不丢** —— 卡片是索引，不是替代品
3. **召回靠线索，不靠全量** —— 被某个词、某个时间勾起来，而不是遍历

## 它到底干什么

### 1. 每轮归档

每一轮的用户原话、回答、用过的工具，都写进 `turns.jsonl`：

```json
{"turn": 249, "seq": 1, "ts": 1792900000000,
 "user": "帮我看看这个 CSV 为什么少了三行",
 "assistant": "查到了，是 `read_csv` 默认把空行当分隔符……",
 "tools": ["read", "pwsh"]}
```

**只存人话，不存思考过程**（reasoning 块丢掉）——那是过程，不是结论。

### 2. 冷层增量（diff）

写归档时，拿这一轮的回答跟最近 20 轮比，找共同前缀最长的当基准，
只存「前缀长度 + 后缀长度 + 中间那段」：

```json
{"turn": 250, "assistantDelta": {"base": 249, "pre": 184, "suf": 12, "mid": "只改了这一句"}}
```

中间那段比原文短 **40%** 以上才启用，否则老实存原文。
**同一件事反复做的时候省得最多**（模板化回答、重复的工具输出）——实测能省 65%。

### 3. 记忆卡

压缩时机有两种：

**① 压力触发**：上下文过 `compactAt`（默认 60%）→ 找任务边界切一张卡

**② 任务级**：回答里出现收尾语（完成/搞定/通过了）且这段攒够 3 轮 → **当场封卡**

卡长这样：

```json
{
  "date": "2026-10-24", "from": 238, "to": 250,
  "title": "给插件加任务级压缩",
  "goal": "加一个任务级压缩：目标达成即封卡",
  "actions": ["pwsh×6", "edit×3", "read×2"],
  "outcome": "测试 125 个全绿，v0.9.0 已推",
  "files": ["D:\\Work\\Code\\FatFishsMemory\\src\\task.js"],
  "keywords": ["压缩", "任务", "封卡"],
  "cut": "task", "cutScore": 1, "span": 12,
  "tokens": 412, "turns": 3
}
```

`cut` 记着这张卡是怎么切出来的：`task`（任务完成）/ `detected`（话题断点）/ `fallback`（对半切）。
单张任务卡最多覆盖 12 轮——防止隔太久后封出一张巨卡。

### 4. 记忆目录（hot memory）

会话开始时，把最近几张卡的标题作为一条 system 消息注入：

```
[记忆目录] 你之前经历过这些（细节需要时再查）：
- 2026-10-24 给插件加任务级压缩
- 2026-10-24 冷层增量归档
- 2026-10-23 白屏事故
（我是谁：~/.dsh/fatfish-memory/persona.md）
（查细节：node ".../tools/recall.mjs" "关键词"）
```

**最后两行是钉子**——即使卡片多到超字数，它们也不会被挤掉。
因为"我是谁"和"怎么查"比记住某件小事更重要。

目录按**内容指纹**去重：内容没变就不重复注入；折出新卡后自动再注入一次。

### 5. 自动查表（auto-recall）

在回答之前，先看看温层和冷层里有没有相关的东西：

```
用户说话
   ↓
① 抽线索（那天/上次/之前/还记得…）
   ↓ 不命中 → 什么都不做，照旧回答
② 命中 → 查卡片索引 + 最近原文
   ↓ 没有相关
③ 有 → 注入一小块「可能相关」（最多 3 条、300 字）
```

注入长这样，**最后一句是故意的**：

```
[可能相关] 你可能会用到这些旧记录（不确定就别用）：
- 2026-10-24 白屏那次：手改 profile 的 package.json
（不确定就别用）
```

查到不等于对，让模型自己判断，比硬塞给它强。

### 6. 用户画像

独立于会话的一个人：身份、偏好、习惯、情绪、在做的事，**加一行滚动的「最近」**。

```json
{"sections": {
  "identity": [{"text": "后端工程师", "at": "2026-10-24"}],
  "recent":   [{"text": "买了件冲锋衣，吃了海鲜刺身", "at": "2026-10-24", "source": "auto"}]
}}
```

**印象怎么更新**（两层，触发方式刻意不同）：

| 层 | 触发条件 | 节流 |
|---|---|---|
| **最近** | 某轮同时出现**时间线索**（今天/明天/上周）+ **状态线索**（累/烦/开心/期待） | 一小时最多一次 |
| **长期** | 压缩出新卡后，某事实**在不同卡片里出现 ≥2 次** | 每次压缩后 |

近期的靠"当下的语气"，长期的靠"反复出现"。**只出现一次的事不值得写进画像**——那是噪音。

## 命令行工具

四个小工具，都直接读数据目录，**不需要 DSH 在运行**：

```bash
# 翻记忆（关键词 + 向量相似度 + 时间衰减）
node tools/recall.mjs --list
node tools/recall.mjs "白屏"
node tools/recall.mjs "插件" --cards

# 改画像
node tools/remember.mjs show
node tools/remember.mjs recent "今天在打战争雷霆"
node tools/remember.mjs add preferences "喜欢先看结论"
node tools/remember.mjs forget recent

# 把画像渲染成一张本地网页（不联网、双击即开）
node tools/profile-page.mjs      # → ~/.dsh/fatfish-memory/profile.html

# 把插件装上之前的历史会话导进来（可反复跑，已有的跳过）
node tools/import-sessions.mjs --dry-run
node tools/import-sessions.mjs --apply
```

**召回打分** = 关键词命中 + 本地 n-gram 向量相似度 × 时间衰减。
衰减半衰期 90 天、下限 0.2——老记忆排后面，但不会被过滤掉。

## 配置

全部在 `cordis.patch.yml`：

```yaml
- insert:
    - id: fatfish-memory
      name: dsh-fatfish-memory
      config:
        enabled: true
        dataDir: ""              # 留空 = ~/.dsh/fatfish-memory
        compactAt: 0.6           # 上下文压力过这个比例才压
        minTurnsPerCard: 6       # 卡片最少覆盖几轮
        archiveTurns: true       # 是否落盘原文
        hotMemory: true          # 会话开始时注入记忆目录
        hotMemoryEntries: 8      # 目录里最多几条
        maxCards: 300            # 卡片上限，超出的进 archive/
        impressions: true        # 自动更新画像印象
        recentEveryMs: 3600000   # 「最近」多久最多更新一次
        taskCompaction: true     # 任务完成即封卡
        minTurnsPerTask: 3       # 最少几轮才算"一件事"
        maxTurnsPerTask: 12      # 单张任务卡最多覆盖几轮
        autoRecall: true         # 问旧事时先查表
        autoRecallMax: 3         # 一次最多注入几条
        persona: true            # 目录里指路到 persona.md
        migrate: true            # 换 dataDir 时自动搬旧数据
        debug: false             # 调试日志
```

调试也可以不改文件：`set DSH_FATFISH_DEBUG=1`（优先级更高，重启生效）。

默认目录也不可用就只读模式运行——**绝不静默降级**。

## 隐私

这是私人记忆，规则写死在代码里：

- **零网络调用**：`src/` 下没有 `fetch`/`http`/`net`
- **零运行时依赖**：`dependencies` 为空，装完就能跑
- **数据只在本地**：默认 `~/.dsh/fatfish-memory/`，不在仓库里
- **仓库兜底**：`.gitignore` 屏蔽 `profile.json`、`turns.jsonl`、`compactions.jsonl`、`node_modules/`
- **可读可删**：全是纯文本，不想要哪条直接删

一句话：**记忆属于用户，不属于仓库。**

## 为什么不做「注入」

早期版本用 `session.append('agent/inbox/spliced', …)` 把画像塞进下一轮。
功能确实跑通了——模型能在输入里看到画像。

但它有**不对称风险**：运行时会给这条消息打上 `source.kind = "plugin:<name>"`，
而它会进入会话事件流。一旦客户端渲染不了这种来源，**整个对话区会白屏**——
一条消息能毁掉一个会话。

现在改为：画像和目录都走 `system/message`（有 `surfaceOp` 标记、有内容指纹去重），
人设写进文件由 agent 自己读。**文件坏了顶多读不到，不会破坏任何东西。**

## 设计决策

- **压缩永远从原文重新生成**，不在旧摘要上二次摘要——避免误差累积
- **中文没有空格**，关键词用 2/3-gram 提取，`服务器` 和 `服务` 才能互相命中
- **不跟框架抢压缩权**：只旁听 `compaction/*`，记录它丢了什么
- **宁可不记，也不要记得错**：查不到就说没有，不编
- **钉子型提示**：目录被挤时先丢卡片，保住"我是谁"和"怎么查"

### 踩过的坑（都留了测试）

| 坑 | 现象 | 修法 |
|---|---|---|
| 手改 `package.json` + junction | 对话区白屏 | 只用官方 CLI；包是拷贝，改代码要升版本号 |
| `system/message` 缺 `surfaceOp` | 被运行时拒绝 | 追加时必须带 `{surfaceOp:'append'}` |
| 在 `turn/start` 注入 | step 还没打开 | 改到 `step/start` 或主系统提示落盘后 |
| 每次重启重复注入 | 上下文越堆越多 | 按内容指纹去重 |
| `user/message` 早于 `turn/start` | 归档里 user 全空 | `turn/start` 不清 `buf.user` |
| 节流戳在没命中时也刷新 | 一小时内真正的情绪被挡掉 | 只在真的写入时更新戳 |
| 任务跨度太长 | 138 轮封成一张巨卡 | 单卡上限 12 轮 |
